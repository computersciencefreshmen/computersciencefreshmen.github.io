# henryyang.blog — GitHub Pages domain switch

The personal website stays on GitHub Pages. This changes its public address,
metadata, share card and eight CV editions, without introducing a paid web server.
Hash navigation and root-relative assets remain unchanged.

## Activation prerequisites

Only activate a custom domain once the owner has purchased it and can control its
DNS. Keep the current github.io site available during preparation. The checklist
below also applies when repeating or recovering this domain setup.

1. Register `henryyang.blog`; domain registration is separate from web hosting.
2. In personal [GitHub Pages settings](https://github.com/settings/pages), add
   `henryyang.blog` as a verified domain. Copy the unique TXT verification value
   generated by GitHub to the registrar and complete verification. Keep this TXT
   record after activation.
3. In [repository Pages settings](https://github.com/computersciencefreshmen/computersciencefreshmen.github.io/settings/pages),
   save `henryyang.blog` as the custom domain before pointing the web DNS records
   at Pages. Merge the tested source change as part of this switch.
4. Configure the records below, replacing conflicting parking records. Wait for
   the Pages DNS check and HTTPS certificate; enable Enforce HTTPS when available.
5. Check the homepage, blog and CV routes, static assets, PDF downloads, metadata,
   sitemap and redirects on both the new apex and `www` names. Check the original
   github.io address redirects as expected.

## DNS records

| Type | Name | Value |
| --- | --- | --- |
| TXT | `_github-pages-challenge-computersciencefreshmen` | Unique value from GitHub personal Pages settings |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `computersciencefreshmen.github.io` |

An ALIAS/ANAME pointing the apex to `computersciencefreshmen.github.io` may replace
the four A records if supported by the DNS provider. Do not guess the TXT token or
create a wildcard record. When the apex is the Pages custom domain, a correctly
configured `www` name redirects to it. DNS and certificate provisioning may take
up to 24 hours.

This repository deploys with custom GitHub Actions. A `public/CNAME` file is
ignored by that publishing mode and is not required; the repository Pages setting
performs the actual binding.

## Validation and rollback

Run `npm run check`, export/regenerate/verify the eight CV PDFs using the existing
scripts, and inspect the changed share image and rendered PDF pages. This branch
must not claim a live-domain check before activation.

If the switch fails, remove the custom domain in repository Pages settings and
restore the previous source deployment so its canonical and sharing links point
back to github.io. Keep the domain-verification TXT record. Removing DNS alone
does not reset the Pages redirect or website metadata.
